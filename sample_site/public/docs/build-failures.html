Builds

Fix a failed build

When a build fails, the deploy stops and the previous release keeps serving traffic, so users are not affected.

Out of memory

The message "killed" or exit code 137 means the build ran out of its 4 GB of memory. Large front-end bundles are the usual cause. Reduce parallel jobs or build the assets in CI and commit the output.

Missing lockfile

Buildpacks need a lockfile, such as package-lock.json or poetry.lock, to install the same versions every time. Commit the lockfile and deploy again.

Works on my machine

If the build passes locally but fails here, clear the build cache, check that every environment variable needed at build time is set, and compare language versions. Pin the runtime version in acme.toml.
